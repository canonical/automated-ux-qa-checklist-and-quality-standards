### 🔍 Needs review

#### Copy & content

- [ ] **Resources section — tab order/structure** — Copy doc lists "Whitepapers" then "Webinars" as separate sections, plus a standalone "Latest from our blog" block. Demo merges all three into a single "Resources" tabbed component with tab order: Blog → Whitepapers → Webinars.
  - Found: Three tabs under one "Resources" heading (Blog first)
  - Expected: Whitepapers and Webinars tabs, with blog as a separate section below

- [ ] **"Learn about all our security certifications" link destination** — Copy doc specifies `https://ubuntu.com/security/certifications`. This URL 302-redirects to `/security/security-standards`. Confirm this redirect is intentional and the copy doc link text is still accurate (it says "certifications" but lands on "security standards").
  - Found: `/security/certifications` → 302 → `/security/security-standards`
  - Expected: A page about certifications specifically

- [ ] **Hero CTA "Contact us" link** — Copy doc links to an anchor in a separate Google Doc (contact form spec). Demo links to `#get-in-touch` opening a modal titled "Contact us about Canonical solutions for NIS2". Confirm modal title/behaviour matches intent.
  - Found: Modal with title "Contact us about Canonical solutions for NIS2"
  - Expected: Copy doc doesn't specify modal title explicitly

- [ ] **"Get Ubuntu Pro" CTA destination** — Copy doc specifies `https://ubuntu.com/pro`. Demo links to `/pro` (relative). Functionally equivalent on ubuntu.com but on the demo domain this resolves to `demos.haus/pro`. Confirm relative URL is intentional for the demo environment.
  - Found: href="/pro"
  - Expected: href="https://ubuntu.com/pro" (or relative, confirmed intentional)

#### UX / Links

- [ ] **"Read the case study ›" — repeated link text** — Three case study links all use identical visible text "Read the case study ›" but go to different destinations. This fails the "links with the same text should go to the same destination" rule. Each tab only shows one at a time, which mitigates the issue, but screen readers listing all links will surface all three.
  - Lucid → `canonical.com/case-study/lucid-aws-fedramp-compliance-case-study`
  - Grundium → `canonical.com/case-study/grundium-ubuntu-pro-for-devices`
  - OEDIV → `canonical.com/case-study/oediv`

- [ ] **"Learn more ›" — repeated generic link text** — Three cloud provider links all use "Learn more ›" as visible text. Aria-labels are set correctly ("Learn more about Ubuntu on AWS/Azure/Google Cloud Platform"), which helps assistive tech. However, the visible text alone is generic and repeated.
  - AWS → `/aws`
  - Azure → `/azure`
  - GCP → `/gcp`

- [ ] **Security certifications link redirect** — `/security/certifications` returns a 302 redirect to `/security/security-standards`. Flag as unexpected redirect.

#### Accessibility

- [ ] **YouTube iframe** — The embedded video uses `title="YouTube video player"` which is generic. Should describe the video content (e.g., "NIS2 compliance with Ubuntu Pro overview").
